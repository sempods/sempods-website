The pages make these distinctions explicit:

- The specification determines the contract independently of Kotlin. Development
  specification labels require a source revision.
- Contexts are part of the selected current core; context lifecycle management is
  optional. Broader ordinary access without Context setup remains proposed.
- Kotlin provides reusable building blocks and a development/evaluation composition.
  Concrete deployments own upgrades and recovery; the supplied composition has no
  supported upgrade path.
- Service access is an experimental Kotlin 0.2 extension. Grants are resolved by the
  server; they are not permissions embedded in an access token.
- Per-pod MCP and hosted multi-pod MCP have different trust and credential boundaries.
  Kotlin 0.2 lacks the required conformance endpoint; no certification is claimed.
- Live events provide evidence. Personal memory, team and museum scenarios illustrate
  possibilities without claiming packaged products, subscriptions or private customers.

Start uses the 0.2 BOM, current client API and per-module Java requirements. It links
release-pinned migration, service and local-setup guides. No untested Docker command,
image download or managed hosting upgrade promise was added.

## Lessons for the workflow

Checking literal Astro URLs missed helper-generated links. Checking a source path
alone missed a guessed MCP guide location and cannot verify heading anchors. Review
built HTML against the actual source revision as well as the source inventory.

Astro can remove newline whitespace beside inline links/code. Review rendered
paragraphs and search snippets; make required spaces explicit. Adjacent action links
also need textual separation so the search index retains complete words.

The local procedure, extraction and consumer are usable now. Unattended release-event
execution, an idempotent PR runner and publishing remain separate implementation work.
No release job, recurring automation, push or publication was activated.

The workflow refinement adds `npm run check:rendered` and `npm run demo:verify`.
The rendered check passed the current build; a deliberately broken HTML fixture was
rejected for joined words, a missing route, missing local anchor, absent source file
and absent source heading. The reusable live-demo check passed at 11:05:14 UTC on
2026-09-30 with three events and HTTP 200 for the query and returned resource.
Clicking Home's Build an app link reached `/start/#build`; the next Tab focused
the release link. The local preview remains available for editorial review.


## Review corrections

PR #16's review found three gaps in the reusable checks. Extraction now compares the
manifest version with `gradle.properties` at the selected tag before writing examples,
in addition to checking the tag's commit. Rendered verification resolves relative
links and images against each page URL, including query-only links and anchors.
The public demo expands JSON-LD with the development-only `jsonld` processor before
checking RDF terms; compact terms, aliases and prefixes preserve their meaning.

CodeQL interpreted the original array membership check as URL substring matching.
The type comparison now uses explicit equality on expanded type IRIs. A regression
fixture rejects an unrelated IRI containing the Event IRI. Expanded literals with
scalar datatype IRIs are excluded from node type-array checks.

Eight offline regression tests passed, covering these failure cases and valid
representations. `npm run check`, `npm run build`, tagged example extraction and the
rendered check passed. The revised public demo passed at 12:42:31 UTC on 2026-09-30:
HTTP 200 for query and event read, three rows. No page content or client dependency
coordinates change in this correction.

## Further review corrections

The next review found that an unrelated Event in a JSON-LD graph could satisfy the
demo check, and that three query bindings could describe only one event. The check
now requires three distinct event URIs. After reading one URI, it checks the expanded
node with that exact identifier for the Event type and startDate. Relative node
identifiers are resolved against the fetched URI.

Rendered verification now includes stylesheet, script, icon and preload links,
media sources and image candidates in `srcset` and `imagesrcset`. Asset existence
is checked without treating a non-HTML asset fragment as a page anchor. Fixtures
cover missing assets, relative paths, escaped filenames and data URLs with commas.

## Consumer cleanup and canonical-origin review

Client installation now runs inside the fixture's server cleanup. A separate inner
`finally` closes the installed HTTP client, while the outer `finally` stops the
server even if installation throws. A published-dependency integration test injects
that exception in a disposable copy and verifies that the consumer exits with the
expected error instead of keeping the JVM alive. It passed; the normal unchanged
client example also compiled and ran on Java 21, checking the response and anonymous
request as before.

Astro and rendered verification now share the canonical URL in `src/data/site.json`.
Absolute and scheme-relative URLs with that origin are checked against local routes,
assets and anchors, including canonical links. Origins are compared by scheme,
hostname and effective port; external hosts and apex pod URLs remain external. Three
new offline regressions cover valid and missing same-origin targets, canonical URLs,
escaped asset names, default ports and a fixture-specific origin.

All 25 offline tests passed. Astro reported no errors, warnings or hints; the build
generated and indexed all 13 pages. Rendered verification passed 211 internal
links/assets/anchors and 24 source links. The public page content and canonical URL
are unchanged.

## Verification input-boundary review

The next review found an older empty-asset path and a language-tag qualifier omitted
from the date checks. Asset attributes now reject empty, whitespace-only and
valueless references with tag/attribute context, including empty `srcset` candidate
lists. Navigation self-links, inline scripts and absent optional media URLs remain
valid. Date bindings reject language tags; JSON-LD language qualifiers are retained
for the same check. Language-tagged names and explicitly typed dates under a
default-language context remain valid.

Reviewing the helper's input contract also found a valid RDF representation that
expansion alone rejected: type and date split across repeated descriptions of one
node. JSON-LD flattening expands and combines those descriptions before validation.
The selected URI and exact type requirements remain covered by existing regressions.

The 17 new boundary cases produced 15 failures against the preceding code; two valid
control cases already passed. All 76 offline tests now pass. Astro diagnostics and
the 13-page build passed; rendered verification passed 250 internal references and
24 source links. The live query and event read passed at 14:43:55 UTC on 2026-09-30.

Earlier fixes had been reviewed case by case, and the offline suite ran only locally.
The procedure now requires an input-contract review of the affected helper before
push. The PR build runs offline regressions and Astro diagnostics as well as the
build. Source, consumer, browser and live checks retain their separate environment
requirements; CI success does not imply that those checks ran.
